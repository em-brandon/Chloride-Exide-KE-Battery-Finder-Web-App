PLAN: PyQt6 Desktop App — Full Pipeline Dashboard (Standalone / Direct DB)
=========================================================================

CONTEXT
-------
Replicate the full Admin Data Pipeline web page as a standalone PyQt6 Windows
desktop app. Connects directly to PostgreSQL using db.py + SQLAlchemy — no
FastAPI server needed. Calls pipeline Python functions directly in a QThread.

Works on localhost today. When moving to production (Amazon cloud split):
  - Web app stays on Amazon
  - Desktop app stays on local machine
  - Just update DATABASE_URL in .env to point at Amazon RDS — zero code changes


DEPLOYMENT SPLIT (future)
--------------------------
  Local machine:   desktop_app/ + pipeline Python code + .env → RDS connection
  Amazon cloud:    FastAPI web app + React frontend + RDS PostgreSQL
  Shared:          Same RDS database — pipeline results land there directly

AUTH (auth.py)
--------------
  from db import SessionLocal
  from models import AdminUser
  from admin_auth import verify_password

  def login(username, password) -> AdminUser | None:
      db = SessionLocal()
      user = db.query(AdminUser).filter(AdminUser.username == username).first()
      if user and verify_password(password, user.password_hash):
          return user
      return None

  No session tokens — desktop app keeps logged-in username in memory.


DB QUERIES (db_queries.py)
---------------------------

get_coverage()
  Exact logic from admin_router.py lines 1358-1429.
  Uses pandas (already in requirements.txt):
    1. pd.read_sql from vehicle_years → normalise model with _norm_model_key → dedupe combos
    2. pd.read_sql from web_battery_validation → merge → count matched / unmatched
    3. Bucket counts: (year // 5) * 5 groupby
    4. web_cache_size: len(json.load(open("cache/web_model_cache.json")))
    5. Raw SQL for master_count and staging_count
  Returns: total, matched, unmatched, pct_matched, master_count, staging_count,
           unmatched_vehicles, total_buckets, resolved_buckets, remaining_buckets,
           web_cache_size

get_staging(page, filter)
  Tables: web_battery_staging
  Columns: id, make_n, model_n, year, battery_code, ah, technology, source,
           engine_cc, fuel_type, staged_at, is_valid, invalid_reason,
           conflict, conflict_detail (JSON text)
  Filter: "all" | "valid" (is_valid=T, conflict=F) | "invalid" | "conflicts"
  ORDER BY make_n, model_n, year; paginated

patch_staging(row_id, ah, technology)
  Validate: ah 20-250, technology in {MF, AGM, EFB, GEL, WET}
  UPDATE web_battery_staging SET ah, technology, is_valid, invalid_reason WHERE id

pre_commit()
  Load all staging rows. For each, check web_battery_validation for existing record.
  Conflict if abs(ah_diff) > 5 OR technology differs (both values non-null).
  Returns: {"conflict_count": int, "conflicts": [...]}

commit_staging(resolutions, committed_by)
  Full transaction:
    1. Load valid staging rows, apply conflict resolutions (keep "staging" or "current")
    2. Upsert to web_battery_validation ON CONFLICT (make_n, model_n, year) DO UPDATE
    3. INSERT web_battery_validation_versions (UUID id, incrementing version_number)
    4. INSERT web_battery_validation_changelog (change_type: added/updated/removed,
       old_values/new_values as JSON text)
    5. TRUNCATE web_battery_staging

discard_staging()
  DELETE FROM web_battery_validation WHERE run_id = (SELECT run_id FROM web_battery_staging LIMIT 1)
  TRUNCATE web_battery_staging

get_versions(page)
  SELECT id, version_number, committed_at, run_id, committed_count, removed_count,
         conflict_count, notes, committed_by, initiated_by
  FROM web_battery_validation_versions ORDER BY version_number DESC
  paginated (20 per page)

get_changelog(version_id)
  SELECT make_n, model_n, year, change_type, old_values, new_values
  FROM web_battery_validation_changelog WHERE version_id = :id
  JSON-parse old_values/new_values TEXT columns

revert_version(version_id, committed_by)
  Read changelog, apply inverse operations (added→delete, removed→insert, updated→restore old).
  Creates new version record with notes = "Revert of version #N".

get_matched(page, search)
  SELECT make_n, model_n, year, ah, technology, source, validated_at
  FROM web_battery_validation
  WHERE UPPER(make_n) LIKE :q OR UPPER(model_n) LIKE :q
  ORDER BY make_n, model_n, year; paginated (50 per page)

get_quotas()
  SELECT provider, calls_made, quota_limit
  FROM api_usage_quota WHERE month = current month (YYYY-MM)
  pct_used = 0 if quota_limit == -1 else calls_made / quota_limit * 100


PIPELINE RUNNER (pipeline_runner.py)
--------------------------------------
class PipelineRunner(QThread):
  Signals:
    log_line        = pyqtSignal(str)
    progress        = pyqtSignal(int, int, str, str)   # processed, total, provider, combo
    phase1_progress = pyqtSignal(int, int)
    finished        = pyqtSignal(dict)                 # {"fetched", "failed", ...}
    error_occurred  = pyqtSignal(str)

  run():
    from pipelines.web_battery_validate import main as run_pipeline
    self._cancel = threading.Event()
    self._pause  = threading.Event()
    result = run_pipeline(
        cancel_event=self._cancel,
        pause_event=self._pause,
        progress_cb=lambda p,t,pv,cb: self.progress.emit(p,t,pv or "",cb or ""),
        log_cb=lambda line: self.log_line.emit(line),
        enabled_providers=self.providers,
        run_id=self.run_id,
        phase1_progress_callback=lambda p,t: self.phase1_progress.emit(p,t),
        phase=self.phase,
    )
    self.finished.emit(result)

  pause():  self._pause.set()
  resume(): self._pause.clear()
  cancel(): self._cancel.set()

No QTimer polling needed — signals fire in real time as the pipeline runs.
After finished signal: refresh CoverageWidget and check staging for StagingWidget.

DONUT CHART (coverage_widget.py)
---------------------------------
Custom QWidget subclass. paintEvent uses QPainter:
  1. Background ring: QPen(QColor("#e2e4e9"), width=14, cap=FlatCap) + drawArc full circle
  2. Coverage arc:    QPen(QColor("#22c55e"), width=14, cap=FlatCap)
                      drawArc(spanAngle = int(pct / 100 * 360 * 16))
                      (Qt arc angles in 1/16ths of a degree, start from 12 o'clock = 90*16)
  3. Centre text:     QFont bold — "X.X%" on top line, small "COVERED" below
set_pct(val: float) → stores val, calls update() to repaint

SEPARATE VS CODE PROJECT?
--------------------------
No. desktop_app/ lives inside the existing repo — it imports directly from
db.py and the pipeline scripts. The local/pipeline machine clones the full repo
and installs Python deps only (no Bun, no Node, no running FastAPI).

3. python desktop_app/main.py
4. Log in as admin — main window shows live coverage stats from DB
5. Start pipeline run — log lines stream in real time
6. Pause / Resume / Cancel work correctly
7. After run: staging panel appears; edit rows, commit, discard all work
8. Version history lists versions; changelog dialog and revert work
9. API quota cards show correct provider usage
10. Close and reopen — coverage stats persist (come from DB, not memory)
